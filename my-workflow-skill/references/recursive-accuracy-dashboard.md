# 재귀 학습 정확도 대시보드

## 목적과 측정 원칙

이 프로젝트의 방향은 **긴 제조 문서를 출처가 있는 원자 사실로 압축하고, 불명확·상충·권한 미비 입력을 같은 가드레일 계약으로 처리하며, 사람이 확인해야 할 사실만 남기는 것**이다.

정확도라는 단어를 과장하지 않기 위해 지표를 다음과 같이 분리한다.

| 지표 | 현재 의미 | 실제 제품 사실 정답률인가? |
| --- | --- | --- |
| 출처 사실 커버리지 | 필요한 DOC-READY 필드 중 1차 출처로 확인된 필드의 비율 | 아니다. 입력의 근거 충실도다. |
| 토큰 절감률 | 원문 대신 인용된 사실 팩을 다음 회기에 전달하여 줄인 토큰 비율 | 아니다. 효율 지표다. |
| 구성 사례 판정 일치율 | 의도적으로 만든 사례의 기대 결정과 실제 계약 출력의 일치 비율 | 아니다. 가드레일 회귀 테스트다. |
| 실제 사실 정답률 | 독립적인 사람 라벨 정답셋과 비교한 원자 사실의 precision/recall | **아직 미측정** |

따라서 아래의 100% 값은 모두 구성된 회귀 사례에 한정된다. 이를 실제 반도체/제조 사실의 정확도 100%로 해석하면 안 된다.

## 현재 상태: 무엇이 실제로 좋아졌는가

| 축 | 기준선 → 현재 | 판정 |
| --- | --- | --- |
| 문서 처리 효율 | 공개 데이터시트 전체 15,837 토큰 → 인용 사실 팩 447 토큰 | **97.2% 절감** |
| 출처 기반 사실화 | 합성 예시의 1차 증거 0/10 → 공개 데이터시트 사례의 4/7 필드 출처 확인 | 범위가 다른 사례이므로 절대 정확도 비교는 금지. 다만 출처 기반 작업으로 전환됨. |
| 불일치 차단 | 미검증 → 구성된 불일치 2/2 탐지 | **100% (구성 사례 한정)** |
| 단일 출력 일관성 | 계약 이전 비정형 결론 → GOAL 10~11의 5개 구성 사례 동일 스키마 | **5/5 (100%, 구성 사례 한정)** |
| 권한 오판 방지 | 합성 `ready`도 운전 승인으로 오인할 위험 → GOAL 10~11의 권한 미비/상충 5개 사례 모두 `authorized` 미출력 | **0/5 부당 승인 (구성 음성 사례 한정)** |
| 실제 제조 사실 정답률 | 공개 데이터시트 3종의 후보 30개 생성, 사람 확정 0/30 | **미측정 — 사람 라벨 전 산출 금지** |
| 시간 제한 임시 채점 | 독립 에이전트 3개, 30개 후보, 완전 근거 일치 29개 | **AI 블라인드 합의 96.7% — 실제 사실 정확도 아님** |
| AI 블라인드 합의 정확도 | 독립 에이전트 3개가 값·인용 페이지를 원본 PDF와 대조 | **29/30 (96.7%, 시간 제약 임시 지표)** |

## 방향성 도식

```text
긴 원문·구두 인수인계·벤더 선언·시험성적서
                 │
                 ▼
      출처가 붙은 원자 사실 / 미확인 / 충돌
                 │
                 ▼
        DOC-READY 문서 판정 (품질 신호)
                 │
                 ├── 미확인 → source-owner 확인 대기
                 ├── 충돌   → blocked-by-conflict
                 └── 근거·권한 충족 → 승인 권한자에게만 전달
                 ▼
  manufacturing-gate/v1 단일 출력 계약
                 │
                 ▼
  운영 권한: denied / pending-authority / authorized
```

핵심은 점수를 높여 `ready`를 많이 만드는 것이 아니다. **근거가 없거나 상충하면 항상 같은 형식으로 멈추고, 근거가 있는 정보만 다음 회기의 압축된 사실 팩으로 재사용하는 것**이다.

## 다음 정확도 측정에 필요한 정답셋

GOAL 12에서 평가 기반을 구축했다. 다음 사람 검수 단계가 끝나야 실제 사실 정답률을 계산할 수 있다.

1. 팀의 사람 1명이 원문을 보고 후보 30개의 `ratified / corrected / rejected / not-reviewable`을 라벨한다. 사람은 AI 판정을 재검수하는 역할이 아니라 정답 근거를 확정한다.
2. 추출 결과와 라벨을 비교해 사실 `precision`, `recall`, 미확인 보존율, 충돌 탐지율을 별도로 계산한다.
3. 품질 목표를 충족하지 못한 유형은 원문 전체가 아니라 실패한 원자 사실과 인용만 다음 재귀 회기에 투입한다.
