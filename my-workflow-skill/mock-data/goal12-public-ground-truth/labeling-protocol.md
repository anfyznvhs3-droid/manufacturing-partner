# GOAL 12: 공개 데이터시트 라벨링·측정 프로토콜

## 현재 상태

원본 PDF 3종과 페이지가 지정된 원자 사실 후보 30개를 보관했다. 후보는 AI가 만든 **출처 기반 학습 후보**이며, 사람 라벨 정답셋이 아니다. 실제 사실 정답률은 아래의 사람 검수 완료 전까지 계산·보고하지 않는다.

## 한 명의 운영자 작업 순서

1. `source-manifest.json`의 SHA-256이 다운로드한 PDF와 일치하는지 확인한다.
2. 각 후보의 `source_id`, 페이지, 영어 `expected_value`를 원본 PDF에서 확인한다.
3. `human_decision`을 `ratified`, `corrected`, `rejected`, `not-reviewable` 중 하나로 기록한다.
4. `corrected`이면 사람이 확정한 값과 페이지를 기록한다. `rejected`이면 사유를 기록한다.
5. `ratified` 또는 `corrected`만 평가용 정답셋에 넣는다. `rejected`와 `not-reviewable`은 정답 수에서 제외하고 후보 품질 개선에 사용한다.

## 평가 입력

추출 모델의 결과는 사람 검수자가 라벨별로 다음을 기록한다.

| 필드 | 의미 |
| --- | --- |
| `label_id` | 후보/정답셋의 고유 ID |
| `reported` | 모델이 해당 사실을 주장했는가 |
| `value_match` | 모델의 값이 사람 확정값과 일치하는가 |
| `evidence_page_match` | 모델이 인용한 페이지가 사람 확정 페이지와 일치하는가 |
| `unknown_reported` | 모델이 근거 없는 사실을 확정 사실로 보고했는가 |

## 지표

- `사실 precision = 값과 페이지가 모두 맞는 reported 사실 / reported 사실`
- `사실 recall = 값과 페이지가 모두 맞는 reported 사실 / 사람 확정 사실`
- `미확인 보존율 = 근거 없는 사실을 확정으로 보고하지 않은 항목 / 검수한 미확인 항목`
- `충돌 탐지율 = 발견한 실제 충돌 / 사람이 확정한 충돌`

`source-anchored` 모드는 스크립트와 입력 형식을 시험하는 용도다. 이 모드의 수치는 절대 실제 제조 사실 정확도로 보고하지 않는다.

## 금지 해석

- 벤더 데이터시트의 부품 사양을 최종 제품의 적합성·안전·규제 준수로 확장하지 않는다.
- 30개 후보가 존재한다는 사실을 사람이 30개를 승인했다는 뜻으로 표현하지 않는다.
- 정확도 점수로 운영 권한을 부여하지 않는다.
