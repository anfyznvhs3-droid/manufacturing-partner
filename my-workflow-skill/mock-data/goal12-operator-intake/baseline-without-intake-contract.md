# GOAL 12 RED: 다중 출처 접수 계약이 없는 기준선

## 독립 기준선 시나리오

한 명의 운영자가 약 20명의 엔지니어에게서 제조 문서, 구두 인수인계, 시험 자료를 받아 검토해야 하는 상황을 독립 에이전트에 제시했다. 기존 스킬·기대 답·파일 경로는 전달하지 않았다.

## 기준선이 잘한 점

- 자료 ID, 출처, 개정, 적용성, 구성 기준선, 요구사항-증거 매트릭스를 제안했다.
- 구두 인수인계를 확인 전 미검증 주장으로 처리했다.
- 충돌을 임의로 선택하지 말고 등록하라고 했다.

## 실패 기준

아래의 우리 운영 계약을 출력 구조로 강제하지 못했으므로 기준선은 통과가 아니다.

| 필수 계약 | 기준선 결과 | 실패 이유 |
| --- | --- | --- |
| 운영자 1명 식별 | 미정의 | 접수·정규화의 책임 주체가 데이터에 없다. |
| 출처 수 1~20 강제 | 미정의 | 20개를 넘는 출처가 들어와도 안전하게 분할·보류할 수 없다. |
| 출처별 원본 위치·수령시각·개정·적용 구성·증거 수준 | 권고 수준 | 누락을 기계적으로 검출할 수 없다. |
| 주장별 출처 참조와 확인 요청의 수신자 | 미정의 | 어떤 엔지니어에게 사실을 되물을지 추적할 수 없다. |
| 단일 `manufacturing-gate/v1` 출력 | 다른 승인 요약 형식 제안 | 입력마다 결론 형식이 달라질 수 있다. |
| `denied / pending-authority / authorized`만 사용 | 조건부 승인 제안 | 우리 계약 밖의 상태가 운영 승인처럼 해석될 수 있다. |

## RED 결론

GOAL 12는 지침을 늘리는 작업이 아니라, 위 필드를 구조적으로 검증하는 `operator-intake/v1` 접수 계약과 회귀 테스트를 추가해야 한다.
