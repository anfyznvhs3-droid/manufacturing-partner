# 공개 제조 검증 스토리 페이지 설계

## 목표

제조 엔지니어가 아닌 대중도 한 번에 이해할 수 있도록, 한 명의 운영자가 최대 20명의 엔지니어 자료를 받아 검증 가능한 하나의 결과로 만드는 과정을 스타트업 IPO 소개 페이지처럼 보여준다. 투자심사·운영승인 화면이 아니며, 공개 설명과 데모를 위한 정적 HTML이다.

## 핵심 메시지

> 흩어진 제조 지식을 출처가 붙은 하나의 검증 가능한 이야기로 바꾼다.

## 화면 구조

1. **Hero**: 제목, 짧은 설명, `검증 흐름 보기` CTA, 현재 임시 합의 지표 96.7%.
2. **문제 카드**: 긴 문서, 암묵지, 상충 자료를 세 장의 카드로 설명한다.
3. **운영 모델**: `20명의 엔지니어 → 1명의 운영자 → 1개의 가드레일 출력`을 큰 숫자와 연결선으로 보여준다.
4. **작동 방식**: 접수 → 원자 사실화 → 충돌 탐지 → 확인 큐 → 단일 출력의 5단계 타임라인.
5. **정확도 이야기**: AI 블라인드 합의 96.7%를 임시 지표로 표시하고, 실제 사람 확정 정확도와 다르다는 주석을 항상 노출한다.
6. **미니 데모**: `벤더 선언`, `구두 인수인계`, `상충 시험성적서` 세 입력 탭을 누르면 동일한 출력 카드가 `확인 필요`, `충돌`, `권한 보류`로 변한다.
7. **출력 예시**: `manufacturing-gate/v1`의 문서 판정과 운영 권한을 일반 언어로 매핑한다.
8. **신뢰와 범위**: 국제표준은 범위 기준이며 인증이 아님, 원본 증거와 출처를 보존한다는 원칙을 공개한다.
9. **마지막 CTA**: “자료를 넣으면 먼저 확인할 사실부터 보여준다.” 정적 데모 재생 버튼.

## 시각 시스템

- 어두운 네이비 배경, 아이보리 본문, 청록색 검증선, 주황색 확인 필요, 빨간색 충돌 경고를 사용한다.
- IPO 소개서의 큰 숫자·짧은 문장·단계별 카드 리듬을 사용하되 금융 용어는 사용하지 않는다.
- CSS는 단일 HTML에 내장해 파일을 열면 바로 실행되게 한다. 외부 CDN과 빌드 과정은 사용하지 않는다.
- 모바일에서는 2열 카드가 1열로 접히고, 연결선은 세로 타임라인으로 전환한다.

## 상호작용 계약

- 탭·버튼은 `aria-pressed`와 `aria-live`를 갱신한다.
- 데모 상태는 `vendor`, `handover`, `conflict` 세 값만 허용한다.
- 어떤 데모 상태도 `authorized`를 표시하지 않는다. 공개 페이지의 최종 상태는 `확인 필요`, `충돌로 중지`, `운영 권한 보류` 중 하나다.
- 애니메이션은 `prefers-reduced-motion`에서 즉시 전환으로 바뀐다.

## 데이터와 근거

- 페이지에 표시하는 숫자와 상태는 `my-workflow-skill/mock-data/goal13-blind-consensus.json` 및 대시보드의 임시 지표와 일치시킨다.
- 96.7%는 AI 블라인드 합의 지표이며 사람 확정 사실 정확도가 아니라는 문구를 Hero, 정확도 섹션, 신뢰 섹션에 반복한다.
- 원본 벤더 PDF와 기술 식별자는 번역·수정하지 않는다.

## 수용 기준

- 파일을 더블클릭해도 빌드 없이 화면이 열린다.
- 첫 화면에서 문제, 운영 모델, 임시 지표를 10초 안에 이해할 수 있다.
- 세 데모 입력이 모두 같은 출력 계약으로 수렴한다.
- `authorized`나 투자심사 판정을 표시하지 않는다.
- 키보드 탭 이동, 명확한 포커스, 명암 대비, 축소 모션을 지원한다.
- 390px 폭과 1440px 폭에서 가로 스크롤이 없다.
